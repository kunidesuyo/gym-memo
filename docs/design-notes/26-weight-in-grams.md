# 26. 重量をグラム整数で持つ（2026-09-23）

ユーザーからの指摘: 「kg 管理だと小数が出る。将来計算するようになったら正確な値が出せないのでは」

### 実測

移行データ 4,194セットで測った。

```
重量の異なり値              102 種類
小数桁数                    整数 3,709 / 1桁 485 / 2桁以上 0
2進で厳密に表現できない値    6 種類（2.7 / 12.7 / 17.7 / 23.6 / 53.6 / 110.8）
                           → 該当セット 17 / 4,194（0.4%）
```

`62.5` や `2.5` は分母が2の冪なので**厳密**。問題は `x.7` `x.6` のような値だけだった。

**誤差の実際の大きさ**: `110.8` を REAL で持つと `110.80000000000000426...`。
誤差は約 4×10⁻¹⁵ kg。総ボリュームを全部足しても 10⁻¹⁰ kg で、**表示桁には一切出ない**。

### それでも変えた理由

精度ではなく2点。

1. **今なら無料、あとから有料** —— 本番データがゼロなので型を変えるだけ。デプロイ後はデータ移行が要る
2. **「この比較は安全か」を毎回考えなくて済む** —— 実際には安全なのだが、そう確信するコストが続く

副次的に `SUM(weight_g * reps)` が整数演算で厳密になる。

### 設計: DB は g、API は kg（検討した3案のうち A）

| | DB | API の契約 | 変更範囲 |
|---|---|---|---|
| **A（採用）** | `weight_g` INTEGER | **kg のまま** | `queries.ts` + インポート |
| B | `weight_g` INTEGER | g | 上記 + web 8ファイル29箇所 |
| C | `weight_kg` REAL | kg | ゼロ（却下） |

**A を選んだ理由**:
- 主目的（保存と SQL 集計の厳密さ）は A で達成される
- **web 側の変更がゼロ**（実際、差分ゼロでテスト46本が通った）
- 保存単位を API 契約が隠すので、将来 mg に変えても web は無傷

B が勝つのは「クライアントで大量の集計をする」場合だけ。バックログのグラフ・PR は
D1 にデータがある以上サーバー集計が自然なので、その判断はグラフを作るときで間に合う。

⚠️ **変換を SQL でやらないこと。** `weight_g / 1000.0` を SELECT に書くとそこで float に戻る。
g のまま取り出して JS で割る。

### JS の number で足りるか（検証済み）

`number` は倍精度だが**整数は 2⁵³−1 まで厳密**。

```
MAX_SAFE_INTEGER      9,007,199,254,740,991
1セットの最大重量           153,000 g
総ボリューム(g×回)      2,516,400,000      → 360万倍の余裕
```

→ **BigInt も decimal ライブラリも不要。** 入れると `SUM()` の扱いが面倒になるだけ。

⚠️ ただし **`kg → g` の `Math.round` は必須**。

```js
1.005 * 1000  =  1004.9999999999999   // 整数にならない
16.08 * 1000  =  16079.999999999998
62.5  * 1000  =  62500                // これは厳密
```

小数2桁を **15万通り総当たり**したところ 1,762 件がこの形で、`Math.round` を挟めば
**小数3桁（g の限界）まで往復が一致**することを確認した。
小数4桁（`0.0625kg` 等）は g では表現できないが、そんなプレートは存在しない。

逆方向の `g / 1000` は安全。整数を1000で割った結果は「その小数値の最近傍 double」で、
同じ小数文字列をパースした値と一致するため往復が崩れない。

### 実 API での確認

```
投入 kg  →  DB(g)     →  API から返る kg
110.8       110800        110.8
62.5         62500         62.5
1.005         1005        1.005     ← 2桁の難しいケース
16.08        16080        16.08     ← 同上
-18         -18000          -18     ← 補助
```
