# 25. スプレッドシートからの移行 —— スキーマ拡張（2026-09-21）

2年分の実データ（Google スプレッドシート）を取り込むための準備。

### 元データの性格

```
268日 / 978セル / 2024-10-10 〜 2026-09-09 / 種目列 27
```

**ワイド形式**（列=種目、行=日付）。セルは `重量×回数×セット数` で、
スペース区切りで複数エントリ。

```
[ミリタリープレス] "マシンショルダープレス　23×10 32×10 36×10×2"
[腹筋]             "デクライン5: 10×3"
[ベンチプレス]      "20×10 40×10 50×10 60×8 70×3 80×1 85× 82.5× 80×1×2"
```

**列ヘッダは「枠」**で、セルには実際にやった種目やマシン設定が書かれている。

| 分類 | 件数 |
|---|---|
| 機械的にパースできるセル | 704 |
| 数値 + テキスト混在 | 231 |
| 数値が取れない | 43 |
| **負の重量**（懸垂の補助） | **140** |
| 日本語テキストを含む | 216 |
| ドロップセット `70×3+60×3` | 6 |
| 回数欠落 `85×`（失敗） | 8 |
| 時間種目 `プランク45s×3` | 2 |

### 決定と対応

| 論点 | 決定 |
|---|---|
| 負の重量 | **スキーマを緩めて負数を許す** |
| セル内の種目名 | **明らかに別種目なら種目として作る。設定系は note** |
| ドロップセット | 2セットに分割 |
| 回数欠落 | **失敗として記録。`failed` boolean をスキーマに追加** |
| 時間種目 | 無視（2件のみ） |

### なぜ負数を許したか

`-36kg → -18kg` という**アシスト量の減少がそのまま上達の記録**になる。
0kg + note に落とすと、懸垂（全体で3番目に多い種目・174セル）の
2年分の進捗が丸ごと失われる。

```ts
weightKg: z.number().min(-500, '補助が大きすぎます').max(1000, '重量が大きすぎます')
```

### `failed` の設計

`85×`（85kg に挑戦して挙がらなかった）を記録できるようにする。

```ts
failed: z.boolean().default(false)
reps: z.number().int().nonnegative()   // 失敗時は 0 を許す

// 成功したセットは必ず1回以上挙がっているはず
.refine((v) => v.failed || v.reps >= 1, {
  message: '成功したセットは回数を1以上にしてください', path: ['reps'],
})
```

⚠️ `.refine()` を付けると `ZodEffects` になり **`.omit()` が使えなくなる**ので、
フィールド定義を素のオブジェクトで持ち、`z.object(...)` した後に refine する構造にした。

画面では回数の代わりに「失敗」を赤字で表示する（3画面すべて）。
フォームには「失敗」チェックボックスを追加。

### 移行の進め方（全て完了）

```
① スキーマ拡張（負数 + isSuccessful + グラム整数）   ✅
② 種目名の分類をユーザーと確定                      ✅
③ インポートスクリプト（apps/api/scripts/）          ✅
④ ローカル D1 に投入 → API で確認                   ✅
```

### スクリプトの構成

```
apps/api/scripts/
  classify.ts             種目 / note / 無視 の分類規則（ユーザー判断をコード化）
  parse-cell.ts           セル1つ → セットの配列
  import-spreadsheet.ts   CSV → SQL 生成
```

⚠️ **1文あたり 500行で分割している。** 全4,194行を1文にすると 616KB になり、
D1（特に remote）の文サイズ上限に引っかかるおそれがあるため。分割後は最大 74KB。

### 個人データの扱い

元 CSV・生成 SQL・ローカル D1 はすべて gitignore 済み（`tmp/` と `.wrangler/`）。

ただし `classify.ts` の `CELL_FIXES` に**実セルの文字列が2行だけ**含まれる
（打ち間違いの修正根拠を残すため）。ユーザー了承済み。
種目名51件も分類規則として含まれるが、これは移行ロジックそのもの。

②用に `tmp/exercises-review.tsv` を書き出し、ユーザーと1件ずつ突き合わせて確定させた。

### 種目の線引き（ユーザー判断）

| 表記 | 扱い | 理由 |
|---|---|---|
| `mag` 系（パラレル / リバース / 逆手 / ナロー…） | **別種目** | ラットプルダウンの**アタッチメント**。重量帯（25〜47kg）も懸垂の補助（負）と別物 |
| `パ`（パラレルグリップの補助付き懸垂） | **懸垂 + note** | 同じ器具の**グリップ違い**にすぎない |
| `デクライン` / `(2)` / `傾斜` / `ノーマルグリップ` | **note** | マシン設定 |
| `マシンショルダープレス` / `インクラインダンベルカール` など | **別種目** | 器具が違う |
| `合トレ(胸)` / `プランク` / `トーソ・ローテーション` / `サイド` | **無視** | メモ、または1〜2件のみ |

**線引きは「アタッチメント = 別種目 / グリップ = note」。**

表記ゆれも吸収した（`magリバース` = `リバースmag`、`ラットプル` = `ラットプルダウン`、
`アイソラネテラル…` = `アイソラテラル…` など）。規則は `apps/api/scripts/classify.ts` に集約。

### 分割に「その他」を追加した

腹筋系（アブローラー84件・腹筋56件）は PPL のどこにも綺麗に入らない。
便宜的に `legs` に置いていたが、ユーザー判断で **4分類目 `other`（その他）** を新設した。

```ts
export const categories = ['push', 'pull', 'legs', 'other'] as const
defaultCategoryFor = { ..., abs: 'other' }
```

DB の `category` は TEXT なので制約変更は不要（TS の型と Zod の enum のみ）。
絞り込み UI のチェックボックスも自動で4つになる。
