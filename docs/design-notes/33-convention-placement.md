# 33. 規約の置き場所を分ける（2026-10-03）

### 問題

`CLAUDE.md` が 224 行に育っていた。**毎セッション必ず読まれる**ファイルなので、
行が増えるほど毎回のコストになる。「規約を足すたびに CLAUDE.md を触る」のも嫌だった。

### 判断を決めた1点

**常にコンテキストに載るか、必要時だけ読まれるか。**

| 置き場所 | いつ読まれるか | CLAUDE.md は薄くなるか |
|---|---|---|
| CLAUDE.md | 毎セッション必ず | — |
| CLAUDE.md の `@docs/x.md` | **毎セッション必ず**（中身ごと展開される） | ❌ 見た目だけ |
| `docs/` に置いてポインタだけ | 読みに行ったときだけ | ⭕️ ただし読まれない危険 |
| **スキル** | **description だけ常時、本体は必要時** | ⭕️ 本当に薄くなる |

→ **スキルだけが「薄くする」と「守られる」を両立する。**
`@` インポートによる分割はコンテキスト削減にならないので採らなかった。

### 規約を4つに分類した

同じ「規約」でも性質が違い、それぞれ別の置き場所が正解だった。

| 種類 | 置き場所 | 例 |
|---|---|---|
| 機械が守れる | **`biome.json`** | `schema/` への Drizzle 混入、feature の依存の向き |
| 手順（読む時が決まっている） | **スキル** | デプロイ、マイグレーション |
| コードの隣でしか意味がない | **`⚠️` コメント** | `toG` の `Math.round`、`UNIQUE` を張るな |
| 読み物として要る | **design-notes** | なぜ UUIDv7 か、検討した代案 |
| 上のどれでもない | **CLAUDE.md** | 地図、コマンド、破ると壊れる一行 |

### やったこと

**1. `deploy` スキルを作った**（30章の218行を移した）

description に「`pnpm run deploy` / `db:migrate:remote` / `--remote` を打つ前に読む」
と書いてあるので、デプロイしようとした時点で読まれる。
本体は普段コンテキストに載らない。

**2. 機械化できる規約4つを `biome.json` に落とした**

`noRestrictedImports` を `overrides` でディレクトリ単位に設定した。

| 元の文章 | lint |
|---|---|
| `schema/` に Drizzle / D1 を import しない | `apps/api/src/schema/**` で `drizzle-orm` / `**/db/**` を禁止 |
| `@hono/zod-validator` を直接 import しない | 全体で禁止（`validator.ts` だけ例外） |
| shadcn の `form` を入れない | `react-hook-form` を禁止 |
| feature の依存は一方向 | `features/exercises/**` から `features/workouts` を禁止、`components/` `api/` から `features/` を禁止 |

⚠️ **設定を書いただけで効いていない、が一番ありがちな失敗。**4つそれぞれ
わざと違反する import を足して検出されることを確認した。

⚠️ `biome.json` には**コメント用の偽キーを置けない**（`additionalProperties: false`）。
理由はルールの `message` に書く。それがそのままエラー文として出るので都合がよい。

**3. CLAUDE.md を圧縮した**（224 → 188行）

冒頭に「知識の置き場所」を置き、**規約を増やすときはまず lint で止められないかを
考える**と明記した。これがないと同じように育つ。

### 残っている判断

**ADR 化は見送った。** design-notes が既に ADR の役をしている
（33章すべてに日付と決定があり、「当初こう書いていたが撤回した」という
Superseded の記録まで入っている）。1決定1ファイルに割る利点は探しやすさだけで、
design-notes は自動で読まれないので行数のコストがゼロ。
**「章を探せなくて困った」という実害が出てから**でよい。

### 追記（2026-10-03）: design-notes を1章1ファイルに分割した

上で「ADR 化は見送った、章を探せなくて困ってからでよい」と書いた直後に
**3,063行は読めない**という実害が出たので分割した。

```
docs/design-notes/
├── README.md                     目次 + 「よく引かれるもの」の表
├── 01-purpose.md ... 33-convention-placement.md
```

⚠️ **章番号は振り直さない。** リポジトリ中に「N章」という参照が **82箇所**ある
（CLAUDE.md 17 / infra/README.md 3 / biome.json 3 / deploy スキル 3 / コード 3 /
design-notes 内 54）。番号をファイル名の接頭辞にすることで、
**番号がそのまま住所**になり既存の参照が全部生きる。

まとめファイル（`01-planning.md` に1〜11章など）は採らなかった。
「17章」から該当ファイルを引くのに索引が必要になり、1ファイルが依然500行を超える。

#### 分割で見つかった問題

サイズ以外に**古くなった章が現役のように読める**問題があった。

- **7章「データモデル（たたき台）」** —— `performed_at` / `weight_kg` / `rpe` のままで、
  実際のスキーマ（`performed_on` / `weight_g` / `category` / `display_order` /
  `is_main_set`）と食い違う。**読むと誤解する**ので冒頭に警告を入れた
- **9章「次に決めること」** —— 全部解決済み

通しで読まない前提の1ファイルになったので、**各ファイルの冒頭に警告を置けば済む**。
3,000行の中に埋もれていたときは誰も気づけなかった。
