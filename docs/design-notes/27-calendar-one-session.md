# 27. ホームをカレンダーに / 1日1セッション（2026-09-23）

移行で267セッション・2年分が入った結果、ホームの「日付＋セット数」の一覧が
**スクロールするだけの画面**になった。週3〜4回の分割トレで知りたいのは
「今週どこをやったか」「何日空いたか」で、それは並びではなく**配置**で見たい情報だった。

### 決めたこと

| | 前 | 後 |
|---|---|---|
| ホーム | 日付＋セット数の縦一覧 | 月カレンダー。記録のある日を塗って押すと詳細へ |
| 同日の複数セッション | 許す | **不許可**（`performed_on` に UNIQUE） |
| 「今日のセッションを始める」 | 毎回 POST | 有れば既存へ遷移、無ければ作って遷移 |
| 種目一覧のセット数 | 表示 | 非表示（**並び順にだけ使う**） |

### 1日1セッションにした理由

分割は1日1つしかやらない。同じ日に2つ作れると「今日の記録」がどれか決まらず、
ホームのボタンもカレンダーの1マスも**分岐できなくなる**。ドメインの制約なので DB で保証する。

三重に守っている。どれか1つでは足りない。

1. **DB** `CREATE UNIQUE INDEX workouts_performed_on_unique` —— 最後の砦
2. **API** `POST /api/workouts` は既存があれば **409**。
   索引違反をそのまま起こすと `onError` の 500 になり、画面が意味を出せない
3. **画面** ボタンを押した時点でキャッシュ済みの一覧を見て、有れば POST せず遷移

3 があるのに 2 が要るのは、一覧が古いことがあるから（別端末で作った等）。
そのため `useCreateWorkout` の invalidate は `onSuccess` ではなく **`onSettled`** にした。
**409 のときこそ一覧が古い**ので、失敗側でも取り直す必要がある。

⚠️ `mutateAsync` を await した後に `create.isError` を見ないこと。
レンダー時点の古い値を掴んで「失敗したのに遷移する」バグになる（18章・21章と同じ轍）。
`try` / `catch` で書き、失敗系のテストを置いた。

### カレンダーは自前で書いた

react-day-picker（shadcn の `calendar`）を入れなかった。

- 欲しいのは「記録のある日だけがリンク」という一点で、day-picker の選択・範囲・
  disabled のモデルとは噛み合わない
- 月末日は `new Date(y, m + 1, 0).getDate()` で取れる。うるう年を自前で数えずに済む
- 依存ゼロで50行

⚠️ 日付キーは必ずローカル時刻で組む。`toISOString()` は UTC なので JST では
**午前9時より前が前日になる**。`dateKey(y, m, d)` に閉じ込めた。

一覧 API から `setCount` を落とした（カレンダーは日付しか使わない）。
副産物として `useAddSet` / `useDeleteSet` の `keys.workouts()` invalidate も不要になった
——セットが増減してもカレンダーは古くならない。

### 部位の整理

- `abs`（腹）を廃止し **`other`（その他）** に寄せた。該当は腹筋・アブローラーの2種目だけで、
  分割(category)が既に `other` なのに部位まで独立させる意味が無かった
- `calves` の表示名を「ふくらはぎ」→ **「カーフ」** に。他が「胸」「肩」「ハム」と短いので揃えた

データ移行は `0001_magenta_gravity.sql` の末尾に手書きで足した
（`UPDATE exercises SET muscle_group = 'other' WHERE muscle_group = 'abs'`）。
drizzle-kit はスキーマ差分しか見ないので DML は生成されない。

⚠️ 絞り込みの「その他」は**分割と部位の両方**に出るようになった。
テストで `getByRole('checkbox', { name: 'その他' })` と書くと2件見つかって落ちる。
`FieldSet` が `<fieldset>` を出すので `getByRole('group', { name: '部位' })` で絞ってから探す。

### 種目一覧のセット数は消したが、並び順は変えない

「セット数の多い順」は**記録画面のネイティブ `<select>` でよく使う種目を上に出す**ための
並びであって（25章）、数字を見せることが目的ではなかった。API は `setCount` を返し続ける。
